# MCode TUI 更新日志

这里记录 MCode
TUI 正式版中用户能直接感知的重要变化。收录范围以 TUI 用户影响为准，而不是以代码目录为准：

- TUI 本身的功能、交互、显示、兼容性、安装和更新变化；
- Runtime、Agent、Tool、Skill 等共享层中会改变 TUI 行为的变化。

仅内部重构、测试调整，或只影响其他产品界面且不改变 TUI 行为的变化不记录。

## 0.5.5 · 2026-09-25

### 体验改进

- Bash 命令自动转入后台时，默认及最大总执行时限延长至 1 小时；显式后台任务未指定超时时也默认保留 1 小时。前台等待 60 秒后可返回任务 ID，转入后台不会重新计时。
- 减少安装包启动时加载的依赖，降低启动依赖体积。

- 改进上下文自动压缩的稳定性：大上下文模型会为回复预留输出空间并更早开始压缩；使用 adaptive thinking 的模型在高推理强度下，不再因思考内容占满输出预算而反复压缩失败。

## 0.4.12 · 2026-09-18

### 体验改进

- 默认状态栏在尚无用量时显示上下文容量，获得用量后自动切换为剩余百分比，避免重复展示上下文信息。

### 问题修复

- 修复会话状态刷新触发重绘时清空终端滚动历史，或导致 Windows Terminal 跳到历史开头的问题。

## 0.4.11 · 2026-09-17

### 问题修复

- 修复 macOS 和 Linux 终端粘贴带转义空格的图片路径时添加失败的问题，兼容长文件名及同时包含反斜杠和空格的文件名。
- 修复登录或退出登录后，顶部登录状态未及时刷新的问题。

## 0.4.10 · 2026-09-17

### 体验改进

- 默认状态栏显示当前上下文总容量，例如 `Context 1M` 或 `Context 512K`；已自定义状态栏的用户可在 `/statusline` 中启用 `context-window`。

### 问题修复

- 新会话及默认模型更新会正确继承所选上下文容量。
- 压缩上下文期间提交的消息会进入等待队列，避免发送失败。
- 已完成的 Shell 命令结果不再在后续对话中重复显示。

## 0.4.9 · 2026-09-16

### 新增

- `mcode exec` 和 `mcode exec review` 支持通过 `--effort` 指定本次运行的思考强度；不支持的档位会在执行前报错，且不会改写会话已保存的强度。

### 修复

- 修复默认思考强度的保存与恢复，使新会话和实际请求使用的强度与模型选择器、状态栏显示一致。
- 模型选择尊重已配置的默认强度和固定档位，并保留关闭思考的设置。

## 0.4.8 · 2026-09-16

### 新增

- Explore 子代理支持使用前台 Bash 检查代码与 Git 状态；沙箱可用时使用只读文件系统策略。

### 改进

- 改善内容审核后的响应处理，支持按审核引导重新生成或返回适用的固定回复，并撤回被拦截的草稿。
- 改善超长思考内容预览时的响应速度，展开详情仍可查看完整内容。
- 运行状态、单轮结束摘要和 Goal 统一使用 `s`、`min`、`h` 显示耗时，超过一小时仍保留秒数。

### 修复

- 恢复支持思考的自定义 Provider 模型的思考开关，保留已有的实际默认行为。
- 修复自定义 Agent 与内置 Agent 同名时的启动失败，并在迁移时保留自定义配置。
- 改善 兼容接口的流式响应取消，避免中断后仍等待数据读取。
- 双击 Esc 或使用 `/edit` 编辑上一条消息时，恢复可操作的图片标签，支持删除、撤销和重新发送；有可读本地文件时可再次预览。
- 修复运行中追加图片或文件时的附件校验失败，并避免已接收的附件随草稿临时文件清理而丢失。

### 新增

- 非交互执行支持通过 `mcode exec --prompt-mode tui|coding|work`

### 改进

- 新添加的自定义 Provider 模型在支持时默认开启可切换的思考模式；保留已有模型设置和显式选择。
- 改善提供 OpenAI 风格模型列表的网关兼容性；连接测试使用模型配置的输出上限。

### 修复

- 改善 MCP 服务名与工具名兼容性、会话间连接隔离，并避免连接测试超时后继续发现工具。
- 修复子任务中后台 Shell 结果未回传的问题，并在子任务结束时清理剩余后台工作。
- 避免自定义 Provider 已开始输出可见内容后重试，导致响应被重复播放。
- 执行异常结束时保留运行中发送的消息，保持会话历史一致。

## 0.3.6 · 2026-09-07

### 问题修复

- 与 MiniMax 桌面端共用数据目录时，官方模型地址改为在 TUI 内按当前环境解析：读取配置和首次初始化不再向共享配置文件写入新的官方地址，避免影响旧版桌面端；自定义（BYOK）服务地址行为不变。

  的安装脚本并保留可选原生依赖；原生模块加载失败时，启动会按安装来源给出对应的修复命令，启动早期错误也会如实报告而不是静默失败。

## 0.3.5 · 2026-09-07

### 问题修复

- 旧版自定义渠道模型的自动修复从启动时扩展到恢复会话和排队消息:遗留模型选择会切换为官方渠道同名模型,同名模型不可用时使用官方默认模型,并保存到对应会话或默认配置;模型列表不再显示遗留渠道入口。
- 响应失败或被停止后,尚未执行的排队消息会保留并显示暂停状态。运行 `/queue` 后按 `c`
  可从队首继续,也可以编辑、恢复或删除待发送消息;暂停期间发送新消息时,可选择先发送新消息再继续原队列,或先清空待发送消息,取消则保留草稿。重新打开会话会显示暂停队列,等待主动继续。
- TUI 内更新改用 MCode 自带的 Node 运行 npm,并在激活前用同一运行时校验新版本的原生模块,修复系统 Node 版本不同导致更新后无法启动的问题;校验失败时保持旧版本可用。
- macOS/Linux 安装器将所选 Node 解析为真实路径,统一用于安装、启动器和安装回执,重跑时按该运行时检查原生模块;同版本安装损坏时自动进入修复安装,无需手动清理安装目录。

## 0.3.4 · 2026-09-06

### 体验改进

- 启动时检测到当前选中的是旧版自定义渠道中的模型时，自动切换到官方渠道的同名模型。

### 问题修复

- `/login` 和 `/logout` 命令始终可用：`/login`
  在已登录时也会向服务端换取新凭据，瞬时刷新失败则保持已登录状态；`/logout` 在已登出时安全跳过。
- 登录凭据被服务端永久拒绝时，自动清除失效凭据并回退到设备授权流程重新登录，修复 `/login`
  反复报错的死循环；临时错误或配置错误不再误清除有效凭据。
- 服务或资源故障时如实报告失败原因，仅在确实需要登录时才提示重新登录。
- 国内账号登录切换到新的认证服务地址。
- 输入草稿恢复失败不再影响正常输入和其他操作。
- 会话历史清单出现重复时自动恢复，避免会话历史加载失败。

## 0.3.1 · 2026-09-04

### 新增功能

- TUI 与 Desktop 统一使用 Shared OAuth Core 管理同一账号登录态；Runtime 与内嵌 `mcode-tools`
  只消费短期 Access Token lease，不读取 Refresh Token。
- 受管 `mcode-tools` launcher 启用前会校验 version lock、package identity、lease protocol 和 CLI
  SHA-256；任一校验失败都保持 fail-closed。
- 新增统一 `/tasks` 任务中心，集中展示 Agent
  Team 和 Runtime 后台任务；Composer 上方使用按严重程度排序的紧凑摘要，并可进一步查看子 Session
  Transcript。
- 新增可选的 `[V]` 机读状态栏和终端结果记录，便于自动化集成；普通状态栏也可展示当前分支对应的 GitHub
  PR 或 GitLab MR。
- 内置 Subagent 可在 Runtime 启动和恢复后保留显式启用的 Web Search 能力。

### 体验改进

- 内部 test / staging 构建支持显式全局参数 `--lane <name>`
  进行 OAuth 联调；prod 构建拒绝该参数，MCode 也不会从环境变量隐式读取 lane。
- Composer 会在提交前区分 Prompt、Command 和 Skill 输入，展示本地化空状态提示，并将无参数 slash 命令后跟随正文的整句按普通提示词发送。
- Provider 配置支持更完整的 models.dev 搜索、更清晰的模型浏览和更安全的 API Key 编辑。
- Queue 和 Steer 在暂停、取消、恢复和后续消息交付期间会持续与当前 Turn 对齐。
- 模型重试、Goal 完成和上下文压缩会展示更清晰的进度与实际 Provider token 用量；Plan
  Review 正文保持在 Transcript 中可滚动查看。
- 安装 MCode 后无需启动 TUI 即可使用受管 `mcode-tools` 命令，更新时会保持包自有 launcher 干净。

### 问题修复

- 非法 grep 正则现在会返回结构化、可操作的 Search 失败信息，并给出按字面匹配的建议，不再直接暴露 ripgrep 原始解析错误。
